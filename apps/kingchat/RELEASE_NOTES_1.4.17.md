## Android update-install note

The Android message “App not installed as package conflicts with an existing package” is generated by PackageInstaller for a package conflict, including incompatible signing certificates. This release keeps the same application ID and uses the same named EAS remote Default keystore selected by the earlier known release build logs. The actual certificate fingerprint of the APK already installed on the user's handset has not been read, so seamless update from an unknown historical or cloned installation cannot be certified from build metadata alone.

Do not tell users to uninstall the existing app until they have considered the local data impact. Guftin's current device-private encryption key is stored locally and is not recoverable after uninstall/reinstall. If a different signing certificate was used for the installed copy, the only data-preserving path is to sign the update with that original key (or a valid Android signing lineage). Removing the old app is a destructive fresh-install path, not an update.


## GitHub runner fallback

The GitHub workflow uses the current Android setup action; SDK licences are accepted once by the action and the native toolchain packages are installed explicitly.

The repository now includes `.github/workflows/guftin-github-local-apk.yml`, which compiles the same Android APK on a GitHub-hosted Ubuntu runner using `eas build --local`. It uses the existing EAS-managed Android keystore; it does not generate a new release key.

Required repository secret: `EXPO_TOKEN` (Expo Owner access token). Never commit the token to source files or print it in logs.

The workflow verifies the APK signature and package metadata, then uploads `Guftin-1.4.17-GitHub.apk` as a GitHub Actions artifact.
